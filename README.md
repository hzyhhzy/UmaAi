# UmaAI/UmaSimulator · [English](README.en.md)

UmaAi 是一个开源的赛马娘育成模拟与决策分析项目。它根据当前回合的结构化游戏状态，评估训练、休息、外出、比赛及剧本动作的长期收益，并给出以最终育成评分为目标的动作建议。

本项目只考虑“凹分”，也就是以最大化育成评分为目标，不考虑用于比赛的赛马娘育成。

目前赛马娘部分剧本的高分纪录是基于本仓库实现的，但由于合规性存在争议，此处不再讲述具体结果。

仓库包含育成模拟器、手写策略、蒙特卡洛搜索、神经网络推理、训练数据生成和模型训练代码，主要用途包括：

- 对于赛马娘育成中的某个回合，给出推荐策略，例如选择哪个训练，或者在剧本中选择哪个升级；
- 定量研究剧本机制和教程攻略，也可以研究某个剧本下的支援卡组强度；
- 作为模型式规划、蒙特卡洛搜索、策略网络与价值网络、搜索蒸馏和近似策略迭代等算法的学习与实验项目。

> 本仓库的 UAF 剧本完成度较高，如果想进一步开发，建议参考 `UAF` 分支。

> 本仓库作者在 2026 年初对《赛马娘》失去兴趣了，所以退游了，本项目也不再维护。感兴趣的开发者可以基于仓库中的代码和 README 说明自行继续开发。现在 AI 编程已经非常强大，适配新剧本应该不会太困难。

## 输入与输出

首先需要通过某些方式，将育成过程中的各种状态，例如支援卡人头分布、当前回合数、当前面板属性和各种剧本加成状态等，转换为结构化的游戏状态。可以基于 OCR、手动输入，或者一些“特殊方式”来实现，具体的方案请你自己研究，本仓库不做介绍。

UmaAi 主程序读取已经结构化的当前回合状态。默认 `MAINAI` 入口支持三种来源：

| `communicationMode` | 状态来源 |
|---|---|
| `localfile` | 读取程序目录中的 `thisTurn.json` |
| `urafile` | 读取 UmamusumeResponseAnalyzer 数据目录中的 `thisTurn.json` |
| `websocket` | 通过本地 websocket 客户端接收状态并回传展示数据 |

主程序收到状态后会：

1. 还原当前 `Game` 并计算训练收益等派生信息；
2. 给出一次神经网络或手写 policy 建议，该过程非常快，但准度较低；
3. 对全部合法动作运行根节点蒙特卡洛搜索，此过程耗时大约十几秒，会给出更精确的建议；
4. 在控制台展示 UmaAI 建议的操作、候选价值和最终评分预测；
5. 在 websocket 模式下将展示数据回传给前端；
6. 等待下一次状态更新并重新分析。

状态采集和实际动作执行由用户或外部前端完成；主程序负责计算和展示决策结果。本程序本身只对已经获取的数据进行分析计算，不涉及对原游戏的修改与操控。

## 算法原理

UmaAi 的算法主干可以分成五个部分。

### 1. 育成模拟器

育成模拟器尽量还原赛马娘的育成机制，包括训练属性公式、各种随机机制、各种剧本机制与公式、评分算法等。它可以从任意中间局面继续模拟到育成结束，运行速度可达每个 CPU 线程每秒约 5000 局。

### 2. 手写策略

手写策略是一套较为简单的人工设计策略。它根据训练属性收益、剧本机制收益等多项因素，快速给出一个较为合理的选择。它可以在蒙特卡洛模拟中完成后续回合决策，也可以为第一代神经网络生成训练数据。

### 3. 蒙特卡洛决策

搜索会遍历当前回合的合法动作。对于每个候选，它复制许多份当前局面，先执行该动作，再由手写策略或神经网络在育成模拟器里继续育成，统计最终得分的分布。每个候选动作通常会模拟 3000～10000 局，可以将蒙特卡洛随机误差降低到约 50 分的量级。

搜索根据最终得分分布选出平均表现或高分上限更好的动作。

### 4. 神经网络（可选）

如果需要更强，可以训练神经网络来代替原先的手写策略。

神经网络接收结构化局面并输出 policy 和 value。policy 用于快速选择 rollout 中的后续动作；value 预测继续育成后的最终分均值和随机波动，可在搜索提前截断时估计剩余未来。

### 5. 搜索驱动的神经网络训练

系统随机生成不同角色、卡组和中间回合，再用蒙特卡洛搜索计算 policy/value 监督标签。第一批数据可以由手写策略完成 rollout。

训练好第一代神经网络后，后续模拟会用神经网络的 policy 输出代替手写策略。神经网络还可以输出 value，因此每次模拟育成可以提前终止，并用网络预测的 value 代替终局评分，从而大幅降低每回合搜索的时间开销。

训练出的网络经外部流程导出并替换当前模型后，可以参与下一批局面生成和搜索。多轮过程形成“手写策略 → 搜索标签 → 神经网络 → 新搜索标签”的近似策略迭代。

## 为新剧本适配 UmaAi

为一个新剧本适配 UmaAi，大致可以分为以下五步。

### 1. 分析剧本机制并实现剧本模拟器

首先需要定量研究新剧本的各种机制，包括但不限于：

- 训练属性计算公式；
- 剧本资源的获得、消耗和加成公式；
- 各类随机结果的概率；
- 固定回合事件及其效果；
- 剧本阶段、特殊训练和最终结算规则。

在此基础上实现剧本模拟器，尽量定量还原剧本本身，使程序能够从任意中间局面继续模拟到育成结束。

部分机制可能过于复杂，或者难以通过实测得到完整公式，例如技能分、支援卡随机事件等。对于这些内容可以采用平均收益、固定补正或简化概率模型等近似方法。只要模拟器与实际育成的整体偏差不大，通常不会使最终策略发生明显改变。

### 2. 建立游戏状态的数据通路

需要自行实现游戏内数据的提取，将当前回合数、面板属性、体力、支援卡人头分布、训练收益、剧本资源等信息转换成 UmaAi 能够读取的 JSON，再由程序还原为内部 `Game` 状态。

考虑到合规性问题，具体的数据提取方式请自行解决，本仓库不做介绍。

### 3. 编写手写策略

可以参考已有剧本的手写策略模板，保留训练属性、体力、失败率、羁绊等通用估值，再加入新剧本资源、阶段目标和特殊动作的价值。

手写策略不必过度追求完美，但也不能太差。一个可参考的标准是：在相同配置下，手写策略的平均育成分尽量不要比游戏高手低 3000 分以上。

可以让程序在内部批量模拟大量完整育成，根据蒙特卡洛多局模拟的平均分观察策略强度，再逐步调整各项估值权重。多局平均分和逐回合动作都可以作为调参参考。

### 4. 检查并适配蒙特卡洛通路

已有代码通常可以提供蒙特卡洛搜索的基本框架，包括复制根状态、固定首动作、后续 rollout、终局评分和结果汇总。

不同剧本可能具有不同的动作集合，例如一个回合内包含多阶段选择、资源购买、状态切换或组合操作。此时需要根据具体机制修改动作编码、合法性判断、首动作执行和候选结果展示，确保搜索能够覆盖本回合所有有意义的策略。

完成前四步后，UmaAi 就已经可以实际使用。只要模拟器和手写策略的质量合格，手写策略配合蒙特卡洛搜索通常可以超过绝大多数普通玩家，但距离理想策略仍有一定提升空间。

### 5. 训练神经网络（可选）

训练神经网络时，需要随机生成大量且覆盖全面的中间局面，并在每个局面上运行蒙特卡洛搜索，获得较高质量的策略和估值标签。

每条训练数据主要包括：

- **输入**：向量化后的当前状态，包括通用育成状态和新剧本状态；
- **policy**：手写策略配合蒙特卡洛搜索得到的动作分布；
- **value**：蒙特卡洛样本的最终平均分及波动，实际实现中可以使用均值和标准差表示。

手写策略经过蒙特卡洛搜索后，决策质量通常会明显高于纯手写策略。神经网络学习这些搜索结果后，即使单独使用 policy，也可以获得强于原始手写策略的快速决策。

第一代网络训练完成后，可以用神经网络 policy 替换蒙特卡洛 rollout 中的手写策略。新的“神经网络 + 蒙特卡洛”组合通常会强于原来的“手写策略 + 蒙特卡洛”，再用它生成训练数据，就可以得到第二代神经网络。

考虑到数据生成和训练开销，以及后续迭代的边际收益，通常训练 1～2 代神经网络就已经足够。继续增加代数往往提升很小，同时需要付出很大的计算成本。

在模拟器精度、局面覆盖和训练质量都合格的情况下，基于神经网络的版本通常可以认为已经接近当前模拟器与评分目标下的最优策略。
